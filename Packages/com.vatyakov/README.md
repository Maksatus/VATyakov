# VATyakov (`com.vatyakov`)

Vertex Animation Textures для Unity 6000.3+ и URP. Анимация запекается в текстуры, а вершинный шейдер Shader Graph
проигрывает её без SkinnedMeshRenderer, Animator и работы CPU на каждого юнита в кадре.

Целевые платформы — iOS Metal (от iPhone 12), Android Vulkan и GLES 3.1+ (Adreno 650 / Mali-G78 и выше).
Целевой масштаб — до ~100 анимированных персонажей в кадре, у каждого свой GameObject с логикой.
Полный план — `Assets/vat-plan-v2.md` проекта-разработки.

## Что умеет сейчас — 0.1.0 (подверсия 1.1)

- **Бейк SkinnedMeshRenderer в Vertex-режиме**: позиции каждого вертекса по кадрам, смещения от позы покоя
  в `_VatPosTex` (RGBAHalf). Анимация блендшейпов, если она есть в клипе, запекается вместе со скиннингом.
- **Клипы Generic, Humanoid и legacy.** Бейк идёт через копию префаба в preview-сцене, сцены проекта не трогаются.
  Foot IK и root motion выключены, данные — в пространстве корня префаба.
- **Один зацикленный клип, ближайший кадр**, без интерполяции. Свет по нормалям покоя.
- **Меши больше 4096 вертексов**: ширина текстуры не степень двойки, лишние вертексы уходят в блоки по высоте.
- **Меш с финальной раскладкой**: два вершинных потока, `baseVertex = 0`, баунды — объединение всех кадров.
- **Ассет `.asset`** с бинарной сериализацией. Повторный бейк обновляет те же объекты, поэтому ссылки из материалов
  и префабов не теряются, даже если меняется размер текстуры.
- **Инспекторы:**
  - профиль бейка заранее показывает число кадров, размер текстуры и память, ошибки и результат;
  - `VatAsset` показывает свой состав и ссылку на профиль;
  - материал показывает, какую анимацию он играет, и обновляет устаревшие данные из ассета.
- **SubGraph `VAT_Vertex`** для своих шейдеров и пример `VAT_Unlit_Vertex`.

Проверено в редакторе (D3D11): VAT совпадает с SMR кадр в кадр. Проверка на устройствах (Metal, Vulkan, GLES)
ещё впереди.

## Как запечь

1. `Create → VATyakov → VAT Bake Profile`.
2. **Персонаж** — SkinnedMeshRenderer внутри префаба или модели (перетащите дочерний объект модели из Project).
3. **Анимация** и **Кадров в секунду**. Зацикленный клип получает `F = max(1, round(L·fps))` кадров.
4. **Запечь**. Рядом с профилем появятся:
   - `<Профиль>_Vat.asset` — `VatAsset` с мешем и текстурой;
   - `<Профиль>_Vat.mat` — материал-шаблон (по умолчанию шейдер `VATyakov/VAT_Unlit_Vertex`).
5. По желанию — **Создать префаб** (MeshFilter + MeshRenderer) для быстрой проверки. Игровые префабы собираются
   вручную.

## Свой шейдер

Добавьте в Shader Graph SubGraph `VAT_Vertex` (`Packages/com.vatyakov/Shaders/SubGraphs`) и подключите его выход
к Position в Vertex-контексте. Свойства `_VatPosTex`, `_VatLayout`, `_VatClipA` SubGraph сам поднимает в итоговый
шейдер. В поле Custom Editor GUI укажите `VATyakov.Editor.VatShaderGUI`.

## Ограничения

- VAT-меш нельзя делать Static и пускать в static/dynamic batching: индекс вертекса берётся из Vertex ID.
- `MaterialPropertyBlock` и `renderer.material` не использовать.
- Enable GPU Instancing на VAT-материалах выключен.
- Вершины запечённого меша не переставлять (`Mesh.Optimize` и сторонние оптимизаторы запрещены).
- Высота текстуры — не больше 4096 строк на ассет: при переполнении бейк падает с понятной ошибкой.

## Устройство

```
Runtime/   VatAsset, VatClip, VatLayoutInfo, VatShaderIds; VatMath — CPU-зеркало VatCore.hlsl
Shaders/   VatCore.hlsl (адресация, клип, кадр), VatShaderGraph.hlsl (обёртки _float), SubGraphs/VAT_Vertex
Editor/
  Framework/  IController, Property, Trigger, EditorContainer, ControllerInspector
  Profile/    инспектор профиля: реестр контроллеров, Context/Model, Controllers/, Containers/
  Asset/      инспектор VatAsset
  Material/   VatShaderGUI — реестр секций
  Ui/         общие элементы: ссылки, плитки, сводка ассета, тексты
  Baking/     VatBaker → VatBakePipeline: Sources/ (кадры) → Layout/ (раскладка) → Vertex/ (энкодер) → VatAssetWriter
Tests/     EditMode-тесты (VATyakov.Editor.Tests)
Samples/   VAT_Unlit_Vertex
```

Бейк — конвейер «источник кадров → раскладка → энкодер → запись ассета». Раскладка считается до сэмплинга, поэтому
ошибки размера видны сразу, а старый ассет не трогается, пока новые данные не прошли проверку. Редакторный UI собран
из контроллеров: каждый отвечает за свою часть инспектора, инспектор только регистрирует их.

`Samples/` на время разработки видима Unity. Перед релизом папку нужно переименовать в `Samples~` и прописать
сэмплы в `package.json`.
