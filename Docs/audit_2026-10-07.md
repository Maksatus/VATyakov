## Коротко

- Ядро сделано хорошо: время на CPU в double, шейдер без ветвлений, CPU-зеркало совпадает с HLSL формула в формулу,
  адресация через `Load`, перебейк сохраняет fileID, ресурсы бейка чистятся при исключениях. Большинство решений
  подтверждено (раздел 4).
- Серьёзные баги — не в ядре, а вокруг него: профили и перебейк (дубликат профиля портит чужой результат, Extra Renderers
  по индексу, устаревшие материалы), семантика рантайма (повторный `CrossFade`, вложенные аниматоры), источники
  (зеркальные трансформы, Alembic из нескольких нод, legacy-клип под обёрткой).
- Главное решение к пересмотру — общий Loop на профиль: его независимо отметили 5 ревьюеров. Из-за него обычного юнита
  (Idle и Run — петли, Attack и Death — one-shot, `CrossFade` между ними) нельзя собрать в одном ассете.
- Главный вопрос скорости — render thread при материале на юнита (6.4 мс на S21+). Дешёвые шаги: одна копия на воина
  вместо двух, не писать материал после законченного перехода в one-shot, убрать аллокацию в `Write`. Архитектуру менять
  только по замеру на Redmi 9A в Release.

## 1. Баги

### 1.1 Дубликат профиля перезаписывает результат оригинала — high (BK-1, UI-1)
`_asset` скрыт (`Editor/Profile/VatBakeProfile.cs:61`), Ctrl+D копирует ссылки на ассет и шаблон,
`VatAssetPath.Resolve` (`Editor/Baking/VatAssetPath.cs:15`) возвращает путь ассета оригинала. Бейк копии переписывает
ассет и шаблон оригинала, при другом Mode меняет шейдер шаблона. Из инспектора ссылку не очистить. Уже случалось в 1.16
(`rbd_test_vat`, откат из git). `VatProfileLookup.Find` отдаёт первый попавшийся из двух профилей.
**Исправление:** в Result — `ObjectField` с `bindingPath = "_asset"`, чтобы ссылку можно было очистить; проблема
валидатора «Asset 'x' is the result of profile 'y' too» (`FindAssets("t:VatBakeProfile")` + `GetDependencies(path, false)`,
без загрузки). Надёжнее — GUID профиля в `VatAsset`, но это меняет формат.

### 1.2 Меши Extra Renderers приживляются по индексу — high (BK-2, BN-2)
`AdoptAll` (`Editor/Baking/VatAssetWriter.cs:63`) копирует новый меш i в старый сабассет i вместе с именем. Удалили первый
элемент [LOD, Axe] и перепекли — в префабе LOD рисует топор, у топора Missing. Перестановка так же молча меняет меши.
Тест удаляет только последний элемент.
**Исправление:** искать существующий меш по имени (`ExtraMeshName` уникален для рендерера), нет — новый сабассет;
лишние уберёт `RemoveStale`. Одинаковые имена рендереров — проблема валидатора. 3–5 строк и тест.

### 1.3 Повторный `CrossFade` в тот же клип перезапускает его с кадра 0 — medium, одна строка (G1)
`VatMixer.CrossFade` (`Runtime/VatMixer.cs:45`) всегда ставит клип в цель с кадра 0 и вес с 0. Обычный код
`if (isMoving) animator.CrossFade("Run", 0.2f);` в `Update`: из Idle юнит едет в позе Idle (вес на записи всегда 0), на
шаблоне без бленда стоит на кадре 0 клипа Run, у уже бегущего юнита `GetNormalizedTime()` всегда 0, `ClipFinished` у
one-shot не приходит. Проверено прогоном логики `VatMixer`/`VatPlayer`/`VatWeightRamp`. Тестов на `CrossFade` в тот же
клип нет, README молчит.
**Исправление:** в начале `VatAnimator.CrossFade(VatClip, float)` (`Runtime/VatAnimator.cs:161`)
`if (clip.IsLooping && clip == _mixer?.Clip) { return; }`. One-shot по-прежнему перезапускается (повторный удар). Три
теста в `VatMixerTests`, строка в README.

### 1.4 Вложенный `VatAnimator` забирает рендереры дочернего — medium (RT-3, DC-4, UX-3)
`CreateCopies` (`Runtime/VatAnimator.cs:158`) берёт все рендереры поддерева, `IsVat` пропускает и чужую копию (у неё есть
`_VatFrame`). Всадник на коне или VAT-флаг на юните: в зависимости от порядка `OnEnable` родитель портит свой `CanBlend`
(`CrossFade` становится мгновенным) либо ребёнок рисуется строками и дрейфом родителя; `Dispose` родителя замораживает
ребёнка.
**Исправление:** брать рендереры, у которых `r.GetComponentInParent<VatAnimator>(true) == this`. Один раз на юнита.

### 1.5 Материалы вне профиля после перебейка со старыми `_VatLayout` и `_VatPosScale` — medium (DT-1, BK-3)
Бейк обновляет только шаблон и материалы Extra Renderers. Копия шаблона (другой `_BaseMap`) после перебейка с другим
числом строк: у Bone пивоты читаются из строки кадра — меш рвётся; у Vertex 8 бит — неверный масштаб; у 2+ блоков —
чужой кадр. Видно только в инспекторе материала, в сборке защиты нет. README обещает перебейк «без потери ссылок из
материалов».
**Исправление:** `VatAsset.ApplyData(Material)` (текстура режима, `_VatLayout`, у Vertex `_VatPosScale`), `ApplyTo` =
`ApplyData` + `ApplyFrame`; в `CreateCopies` вызвать для каждой копии — 2–4 `Set*` на спавн, без MPB.

### 1.6 Template Material с не-VAT шейдером молча становится VAT-материалом — medium (UI-2, DC-7, G6)
`VatTemplateShader.TryFit` (`Editor/Baking/VatTemplateShader.cs:27`) переключает шейдер любому материалу без
VAT-текстуры режима. Template Material = `warrior.mat` (URP Lit исходного персонажа) → после Bake SMR-персонаж во всех
сценах рисуется VAT-шейдером. Без Undo, только `Debug.Log` (`Editor/Baking/VatTemplateMaterial.cs:34`). Свой граф шаблона
при откате Bone → Vertex и обратно тоже теряется молча.
**Исправление:** в `MaterialProblem` (`Editor/Baking/VatBakeValidator.cs:110`) и для каждого `extra.Material` — ошибка,
если у материала нет `_VatFrame`; `TryFit` тогда меняет шейдер только между VAT-шейдерами. `Debug.Log` подмены →
`Debug.LogWarning` с именем прежнего шейдера.

### 1.7 Зеркальные трансформы выворачивают меш — medium (VX-1, BN-3, AB-2)
Позиции переводятся в пространство корня с отражением (det < 0): знак тангента учтён, порядок индексов — нет. Unity у
исходника сама меняет culling, VAT-меш под корнем без отражения показывает изнанку. Случаи: Model со scale.x = −1
(зеркальный вариант юнита), левый щит — копия правого (MeshRenderer экипировки), нода .abc с отрицательным масштабом в
Vertex. В Rigid это уже решено в 0.16.1 (`VatSourceWinding.Reversed`).
**Исправление:** тот же хелпер при det < 0 в `VatSkinnedFrameSource` (`:32`), `VatBoneSkin` (`:21`),
`VatAlembicReader.SourceMesh`. 3–4 строки и тест на зеркальной риге.

### 1.8 Alembic в Vertex из нескольких меш-нод рисует только первую — medium (AB-1, VX-3, SM-1)
`VatAlembicReader.cs:33` — `Combine`: сабмеш на ноду. С одним шаблоном виден сабмеш 0, с N материалами — N draw call на
юнит. В PROGRESS записано как «кандидат на исправление».
**Исправление:** `MergeSlots`, как у Rigid; `Combine` удалить; тест «`vat_rigid.abc` через `VatAlembic.Open` →
`subMeshCount == 1`». Сразу же — предупреждение, что Vertex игнорирует видимость нод .abc (AB-3), и предупреждение, если UV
нет только у части нод (AB-8).

### 1.9 Legacy-клип сэмплируется на корне префаба — medium (VX-2)
`clip.SampleAnimation(_root, …)` (`Editor/Baking/Sources/Skinned/VatClipPlayer.cs:32`), `_root` — корень всего префаба.
Обёртка над FBX (корень со скриптами → модель с Animation): пути кривых не находятся, все кадры = покой, бейк «успешен».
**Исправление:** объект анимации — `Renderer.GetComponentInParent<Animation>(true)`, для Mecanim так же с `Animator`.

### 1.10 Экипировка теряет анимацию промежуточных трансформов — medium (BN-1)
MeshRenderer крепится к ближайшей кости из `smr.bones`, всё между костью и рендерером считается неподвижным. Кость-хват
`weapon_r` без весов в `smr.bones` не попадает — анимация хвата и самого рендерера (достать или убрать оружие) теряется,
а ошибка бейка 0 мм: эталон строится той же формулой.
**Исправление (минимум):** на каждом кадре сверять `bone.worldToLocalMatrix * mr.localToWorldMatrix` с сохранённой,
расхождение — проблема бейка (≈15 строк). Вариант-решение: рендерер — отдельная кость рига.

### 1.11 Root motion запекается в позу без предупреждения — medium (G2)
Legacy-клип и Generic с Root node = None (Mixamo без In Place) запекают проезд таза: меш убегает от GameObject, на шве
петли прыгает назад, при переходе съезжает, bounds растягиваются на весь путь. `02-modes.md` обещает «Root motion не
запекается».
**Исправление:** предупреждение в `VatSkinnedFrameSource.Warnings` (сейчас всегда пусто, `:21`), если `rootBone` за клип
сдвинулся по XZ больше 5 см; поправить 02-modes и README. Не вычитать.

### 1.12 «Out of date» не видит переэкспорта FBX, если Source в префабе — medium (BK-4)
`VatSourceHash.AppendSkinned` (`Editor/Baking/VatSourceHash.cs:48`) хэширует файл, где лежит Source (`warrior.prefab`), а
импорт префаба не зависит от меша и аватара; у Extra Renderers — только путь и тип.
**Исправление:** добавить `DependencyHash` от `sharedMesh`, аватара Animator и мешей Extra Renderers (4–6 строк; хэши
старых бейков один раз сменятся).

### 1.13 Мелкие баги — low
- Speed, изменённый в инспекторе в Play mode, не действует, а геттер возвращает новое значение (RT-6, UI-5, DC-9, UX-9,
  SM-8): `private void OnValidate() { _mixer?.SetSpeed(Now, _speed); }`. Смена VAT Asset в Play mode даёт
  `IndexOutOfRangeException` в `Drift` — выключать поля Asset и Clip в Play mode.
- Копии на ни разу не активированном объекте утекают до конца сессии (RT-5): `DontSave` включает `DontUnloadUnusedAsset`
  (`Runtime/VatMaterialCopies.cs:88`) → `DontSaveInEditor | DontSaveInBuild`.
- Пауза переживает `Play` и возврат из пула (RT-8): решить и записать в §1.6 (или `Resume` в `OnEnable`).
- Кость со scale 0 (спрятать стрелу) откатывает весь ассет в Vertex (BN-5): формат держит s = 0 — кодировать s = 0 с
  поворотом прошлого кадра, ≈8 строк (`Editor/Baking/Bone/VatSimilarity.cs:32`).
- Rigid: кусок, который скрылся и появился снова, и шов петли — кусок «прилетает» за один интервал (RG-2); лимит 2048
  «после выброса невидимых» недостижим из профиля — оценка без `Math.Min` выключает Bake (RG-4).
- Одноимённые соседи — копия бейка берёт не тот рендерер (BN-9): сопоставлять по индексу `GetComponentsInChildren`.
- Отмена бейка показывает диалог ошибки (BK-9); откат Bone → Vertex падает на высоте 4096 без причины отката (BK-8); Bake
  сохраняет все грязные ассеты проекта (BK-12).
- Unlit-сэмпл не подключает Normal и Tangent: тени с normal bias и DepthNormals идут по нормалям покоя (SH-4).
- Инспектор материала: при нескольких материалах ложный текст; на копиях в Play mode во время перехода мигает «stale»
  (UI-12).
- Humanoid-клип без Humanoid-аватара печётся неподвижным без ошибки (VX-4, UX-5). Общее предупреждение «клип не двигает
  меш» (max |Δ| = 0) закроет и это, и 1.9.
- Бейк не вычисляет Constraint и Animation Rigging, Bake в Play mode не заблокирован (G3): строка в README, предупреждение
  валидатора при `IConstraint`/`RigBuilder`, `VatBakeException("Exit Play mode to bake.")`.
- Optimize Game Objects (BK-7, BN-7, не проверено в редакторе): валидатор читает пустые `bones` исходника и советует
  Vertex, хотя копия деоптимизируется. Проверить на FBX, минимум — честный текст.

## 2. Производительность

### 2.1 После `CrossFade` в one-shot юнит пишет материал каждый кадр навсегда — high, одна строка (RT-2)
`VatMixer.Evaluate` (`Runtime/VatMixer.cs:92`) двигает исходный клип и при w = 1. Run → `CrossFade("Death")`: трупы стоят
столько же, сколько живые (SetVector и перезаливка CBUFFER на render thread). §1.6 обещает обратное.
**Исправление:** при `frameB.w == 1f` отдавать `frame = (frameB.x, frameB.y, frameB.z, 0)` — картинка та же,
`SetWeight` назад работает. Тест.

### 2.2 Аллокация в горячем пути — medium, тривиально (RT-1, UX-2, SM-2)
`foreach` по `IReadOnlyList<Material>` (`Runtime/VatAnimator.cs:192`, `Runtime/VatMaterialCopies.cs:13`) боксирует
энумератор: ~40 Б на юнита за кадр, 500 юнитов при 60 fps ≈ 1.2 МБ/с мусора. Единственная аллокация рантайма.
**Исправление:** внутреннему `VatMaterialCopies.Materials` тип `List<Material>` (публичный `VatAnimator.Materials`
оставить `IReadOnlyList`), тест `Is.Not.AllocatingGCMemory()`.

### 2.3 У воина две копии материала на юнита (DC-1, RT-4)
`warrior_axe_vat.mat` отличается от `warrior_vat.mat` только `_Smoothness` (0.6 против 0.2): 800 грязных материалов на 400
юнитов. Очистить Material у Axe в профиле `warrior`, перемерить stress. В `budgets.md`: каждый уникальный VAT-шаблон
юнита — ещё одна копия на кадр (сейчас там «копия материала на юнита»).

### 2.4 Материал на юнита на слабом CPU (DC-2)
6.4 мс render thread на S21+ при 400 юнитах (IL2CPP Development). Ядра A53 у Redmi 9A по оценке в 5–7 раз медленнее —
400 юнитов не влезают в 33 мс (экстраполяция, не замер). Порядок: (1) 2.3; (2) замер в Release и вариант «все на паузе» —
понять, что дорого: перезаливка грязных материалов или смена материала на draw; (3) Redmi 9A; (4) только если не хватит —
индекс юнита через `Renderer.SetShaderUserValue` и общий буфер состояний (проверить на 6000.3 и GLES), MPB не нужен.

### 2.5 Невидимые юниты пишут кадр (G7)
Цена только на main thread, render thread невидимых не рисует. «В лоб» `renderers[0].isVisible` нельзя — LOD1 застынет.
Если делать: «виден любой рендерер с копией» и `_hasWrittenFrame = false` в `OnEnable`. Сначала замер.

### 2.6 Мелкое
- `_VatFrameB` вне перехода переписывается нулём каждый кадр (RT-7) — доли микросекунды.
- Целочисленное деление в `VatTexel` (SH-5, DT-4, DC-10) — только Vertex; трогать после `malioc`/PVRShaderEditor.
- Редактор: инспектор ассета на каждое выделение делает полный Validate и Alembic-пробу, кэш пробы на одну запись (UI-4);
  Validate дважды на изменение профиля (UI-9); 8-битная ошибка — 12 нативных вызовов half на вертекс-кадр, хватит таблицы
  на 256 значений (VX-6); Rigid-острова на гранёных обломках — `Matrix4x4` на остров и отсчёт, прогресс закрывается до
  слияния (RG-3, память записана в PROGRESS).

## 3. Решения: что пересмотреть

### 3.1 Общий Loop на профиль (1.6) — пересмотреть (BK-5, VX-8, UI-3, DC-5, UX-1)
`CrossFade` работает только внутри ассета, поэтому Idle/Run + Attack/Death не собрать: при Loop = On смерть повторяется и
`ClipFinished` не приходит, при Off бег останавливается и дублирует кадр на шве. У воина уже выкинули Attack. Ограничение
только в `VatClipRequest.From`: раскладка, энкодеры и рантайм поклиповые.
**Предложение:** Loop клипа из Loop Time (`AnimationClip.isLooping`; `VatClipPlayer.Wraps` уже это читает), поле профиля —
для Alembic. Для старых профилей — режим From Clip / On / Off или разовый перебейк (у legacy-клипов лука Loop Time может
быть выключен). Флаг клипа — в хэш. Формат ассета не меняется.

### 3.2 Шов петли с нечётным числом оборотов — только предупреждение (SH-1, DT-2)
Решение исполнителя, не пользователя. Колесо, пропеллер, петля-волчок: раз за цикл объект за интервал кадра
проворачивается назад примерно на 345° (во всех трёх режимах), художник исправить не может.
**Предложение:** у loop-клипа строка-замыкание F — копия кадра 0 с q, выровненным по F−1; в `VatClip.Frame`
(`Runtime/VatClip.cs:76`) `frame1 = frame0 + 1` всегда. +1 строка на петлю (воин 141 → 145), шейдер не меняется, уходят
`SeamCount`, `CloseLoop`, `FirstSeam`, `IsSeamShown`, `VatBakeLog.Seams` и подсказки. Поднять `formatVersion`. Объём
средний: раскладка, три энкодера, дрейф, скрытые кадры Rigid.

### 3.3 Масштаб в §0 (DC-11)
В `00-decisions.md` «до ~100», цель 1.14 — 500, бюджеты на 400. От масштаба зависит «материал на юнита» — см. 2.4.

### 3.4 Откат Bone → Vertex (BN-4, BN-5, DC-7)
Проверка остатка `Residual <= MaxResidual` дублирует точную ошибку на вертексах и откатывает ассет при ошибке 0.27 мм —
убрать её, решать по ошибке 0.5 мм. Сжатие в 0 — s = 0 (1.13). Подмена шейдера — `LogWarning`. Вариант «откат = ошибка
бейка» (одно правило с Extra Renderers) противоречит решению §0 — на ваше усмотрение.

### 3.5 «Конструктор» и сборка юнита (DC, UX; скептики отсеяли как противоречащее 0.12.1 и 1.10 — вопрос к вам)
Префаб юнита собирается руками: 5 шагов, у воина около 12. Расхождения (чужой меш, материал другого ассета, Static) молчат и
в редакторе, и в игре. Варианты: пункт меню VAT-ассета «Create Unit» (40–60 строк редактора) или проверки в инспекторе
`VatAnimator` — хотя бы «материал от другого ассета» (`VatMaterialBinding.Read` уже умеет) и Batching Static.

### 3.6 События клипов и точки крепления (G5)
`AnimationClip.events` молча теряются; кадр удара — только порогом `GetNormalizedTime`. Сохранить события, кроме бейкера,
некому. Минимум — предупреждение бейка при событиях в клипе и раздел «Ограничения» в README. Лучше — `VatClipEvent[]` в
`VatClip` и событие рядом с `VatEndLatch` (около дня с тестами). Сокеты костей — отдельно, по образцу `_drift`.

### 3.7 Синхронная толпа (G4)
Play On Enable всегда стартует с фазы 0, юниты одного кадра шагают в ногу; обе толпы VatDev обходят это вручную. Поле
Random Start (3 строки) или строка в README.

### 3.8 Мелкие решения
- Rigid Deform без масштаба (RG-1): сжатие обломка в 0 валит бейк советом «use Mode = Vertex». Минимум — текст «export
  with Packed Transform = Transform Geometry», расширение — масштаб по Umeyama из уже посчитанной матрицы Хорна.
- У Bone нет проверки fps между кадрами, хотя §2.1 на неё ссылается (BN-6): до ~1 см на быстрых клипах при 30 fps.
  Поправить §2.1 или проверка по серединам интервалов.
- Поле Shader профиля работает только на первом бейке и у Bone вводит в заблуждение (BK-10, UX-8) — удалить.
- Mode по умолчанию для Skinned — Bone (UX-7): неподходящий сам откатится в Vertex.
- `versionDefines` Alembic без верхней границы (AB-5) → `"[2.4.5,3.0.0)"`.
- `Play(string)` с неизвестным именем падает `IndexOutOfRangeException` без имени клипа — та же ошибка, но
  `ArgumentException` с именем клипа и ассета (только строковые перегрузки).

## 4. Подтверждённые решения
Время, Loop/one-shot, скорость и вес — на CPU в double, шейдер — адрес, 2 выборки и `lerp`, без `if` и `?:`; MPB запрещён;
два шейдера (с блендом и без) без keyword; дрейф во float32 на CPU, минимум 8-битного диапазона внутри `_VatDrift`;
позиции half или 8 бит по Max Position Error, шейдер один; кватернион RGBA8, `lerp` текселей до декода, однородные N и T;
`LOAD_TEXTURE2D_LOD` по целому адресу; без блочного сжатия, высота ≤ 4096; Bone — две кости, вес
`dot(bytes, (256, 1)/65535)`, до 256 костей, строка пивотов; Rigid — свой SubGraph, 16-битный индекс (точен в half на всех
2048), Horn вместо SVD, подгонка только на настоящих отсчётах; перебейк через `CopySerialized` и выгрузка мешей; ассет
пишется только после успешного пайплайна; оценка тем же `VatLayout`; «Out of date» через dependency hash; время снаружи —
тесты в EditMode; эталоны тестов независимы от бейкера; motion vectors — в патч 2.

## 7. Тесты
- HLSL ни разу не исполняется (TS-1): все декоды сверяются с C#-копиями. Compute-зонд, который вызывает функции
  `VatShaderGraph.hlsl` на текстурах in-memory бейков и сравнивает с `VatMath`/`VatBoneDecoder` при frac ≠ 0 и w ≠ 0, —
  самый ценный тест.
- `VatAnimator` в Play mode не покрыт (TS-2): один `[UnityTest]` — число копий, `ClipFinished` один раз, пул без роста
  Materials, при `CanBlend = false` нет `_VatFrameB`, после Destroy — снова шаблоны.

  `hlslDeclarationOverride` (SH-2); компиляция под GLES3, Vulkan и Metal (SH-6); тип `VertexDescription.Position` в
  Half-родителе (SH-3).

  (TS-9); блендшейп в Vertex против независимого эталона (TS-6); foot IK (TS-11); временные папки без `IsValidFolder`
  (TS-10).
- По тесту на каждое исправление раздела 1–2: удаление первого Extra Renderer, дубликат профиля, хэш при смене меша в
  префабе, зеркальная рига, обёртка над legacy, Alembic из двух нод, повторный `CrossFade`, w = 1 в one-shot, Rigid-петля и
  повторное появление.
