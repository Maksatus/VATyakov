## 2. Режимы

### 2.1 Bone — персонажи из SMR (этап В, подверсии 1.11–1.14)

**Данные** (каналы — §1.9):
- **`_VatBoneTex`:** в строках кадров на кость 2 тексела: `(Δ.xyz, s)` и `q`, где `Δ = p_pose − p̃_bind` — смещение сустава от позы покоя; последняя строка — пивоты `p̃_bind` (уже округлённые до half). Клипы со строки 0, как в Vertex (1.11, §1.9).
- **Меш:** bind-поза в Position (в пространстве корня префаба), две кости и 16-битный вес в TexCoord6 (§1.7, §1.9, 1.12).
- **Память:** 16 Б на кость-кадр. Хранятся все `smr.bones` (индексы рига общие для LOD и экипировки, 1.13); до 256 костей (индекс — байт, 1.12).
- **LOD, скины, экипировка** (1.13): Extra Renderers профиля, только Bone. Один бейк — одна bone-текстура и меш на каждый рендерер (`VatAsset.ExtraMeshes`). SMR переводится в индексы рига основного SMR по `Transform` (порядок и набор костей могут отличаться), bindpose каждой используемой кости совпадает с ригом поэлементно до 1e-4; его bind-поза — `A · v_mesh` той же A, что у основного меша (Unity скиннит через bindposes, трансформ SMR не важен). Mesh Renderer под костью — 100% на ближайшей кости-предке b, позиции `A · bindpose_b⁻¹ · (W2L_b · L2W_mr) · v`: хват — его положение под костью, промежуточные трансформы не анимируются. Проверки разложения, ошибка и капсулы — по вертексам всех мешей. Откат в Vertex с Extra Renderers — ошибка бейка.

**Режим выбирает профиль** (1.11, решение пользователя): поле Mode (Vertex / Bone) у источника Skinned Mesh Renderer, Alembic — только Vertex. Если хоть одна кость с вертексами не раскладывается в `s·R` (отражение, вырождение, неравномерный масштаб) или у меша ненулевой вес блендшейпа на каком-то кадре, весь ассет печётся в Vertex: в одном ассете один меш и один шейдер, поклипового отката нет. Причина (клип, кадр, кость, остаток и ошибка или имя блендшейпа) — предупреждение в логе бейка и HelpBox в инспекторе ассета и в Result профиля. Шаблон, чей шейдер не играет режим ассета, получает шейдер по умолчанию этого режима с сохранением бленда (`vat_lit_bone_blend` ↔ `vat_lit_vertex_blend`). Кости без вертексов не проверяются.

**Шейдер** (1.11, 1.12): SubGraph `vat_bone` и `vat_bone_blend`, графы `vat_lit_bone` и `vat_lit_bone_blend`. С 1.12 вариант один — две кости на вертекс (решение пользователя: без поля Skin Weights, ключей и однокостного шейдера; в 1.11 была одна кость): 10 выборок (2 пивота + 2 кости × 2 кадра × 2 тексела), с блендом — 18. Нормаль и тангент — `rot(q, n)` и `rot(q, t)` меша (§1.9), знак бинормали — `tangent.w` меша.

**Скиннинг:** `v' = Σ wᵢ·(sᵢ·rot(qᵢ, v − p̃_bindᵢ) + p̃_bindᵢ + Δᵢ)`. Между кадрами lerp Δ и s, lerp q: знак q выравнивает бейкер, как в Vertex (§1.3, 1.8.2). В шейдере без `normalize` и `?:`: однородный `rot` даёт `|q|²·R·v`, позиция делится на `|q|²` (§1.9). N и T так же, но без трансляции и деления, нормализует URP.

**Разложение skin-матрицы:**
- `M = root⁻¹ · L2W · bindpose · A⁻¹` (A — renderer→root копии на старте бейка), B — линейная часть M;
- `det B ≤ 0` (отражение или вырождение) — весь ассет печётся в Vertex с сообщением (1.11);
- `s = cbrt(det B)`, R — полярное разложение B (итерация Ньютона `X = (X + X⁻ᵀ)/2` в double, `VatMatrix3d`);
- **равномерный масштаб:** остаток `‖B − sR‖/s ≤ 1e-3` и ошибка `‖(B − sR)(v − p_bind)‖` на вершинах кости не больше 0.5 мм, иначе весь ассет уходит в Vertex (1.11). Ортогональность самого R не проверять: у полярного разложения она есть всегда;
- `p_bind` — только из bindposes;
- `p_pose = M·p̃_bind` считается от уже округлённого пивота, `Δ = p_pose − p̃_bind`.

**Бюджеты ошибки:** на кадрах бейка — меньше 1 мм, включая квантование Δ, q и весов. Бейкер меряет фактическую ошибку восстановления (half-данные и формула шейдера против скиннинга Unity на две кости, по всем вертексам и кадрам): она в `VatPrecision.Error`, в логе и в инспекторе; больше 1 мм — предупреждение в логе (лук — 0.24 мм при одной кости в 1.11, 0.235 мм при двух в 1.12). Между кадрами ошибка интерполяции больше (до ~1 см на быстрых клипах при 30 fps), её оценивает предупреждение о FPS (§2.3).

**Influences:**
- на мобилках максимум 2 (уровень Mobile в проекте уже использует `skinWeights: 2`);
- в пакете всегда 2 (1.12): отдельного шейдера на 1 influence для дальних LOD нет, вертекс с одним весом ставит обе кости на неё;
- `_VAT_BONES_4` — только desktop: на Mali 4 influences спиллят регистры. На мобильных сборках вырезается.

**Бейкер `VatSkinnedFrameSource`:**
- **Копия для бейка, один раз перед всеми клипами:** `animator.enabled = true`, `runtimeAnimatorController = null`, `AnimatorUtility.DeoptimizeTransformHierarchy`.
- **Перед каждым клипом — сброс:** все трансформы из снимка позы по умолчанию и веса блендшейпов, иначе результат зависит от порядка клипов.
- **Generic и Humanoid:** PlayableGraph, `applyRootMotion = false`, `SetApplyFootIK(false)` явно (у нового playable foot IK включён):
  ```csharp
  var g = PlayableGraph.Create("VatBake");
  g.SetTimeUpdateMode(DirectorUpdateMode.Manual);
  var output = AnimationPlayableOutput.Create(g, "out", animator);
  var cp = AnimationClipPlayable.Create(g, clip);
  cp.SetApplyFootIK(false);
  output.SetSourcePlayable(cp);
  try {
      for (int k = 0; k < F; k++) {
          cp.SetTime(k / fpsEff);
          g.Evaluate();
          // снять позы костей
      }
  } finally { g.Destroy(); }
  ```
  `g.Play()` и прогрев `Evaluate(0)` не нужны.
- **Legacy-клипы:** `clip.SampleAnimation`.
- **Root motion не запекается.** VAT-анимация всегда на месте: юнита двигает геймплей, он же задаёт скорость клипа под скорость движения через `VatAnimator.Speed`.
- **Перевод в пространство корня префаба** (FBX: −90° по X и скейл 0.01).

### 2.2 Vertex — деформации, ткань, жидкости с постоянной топологией (этап А, подверсии 1.1–1.5)

**Данные** (каналы — §1.9):
- **`_VatPosTex` RGBAHalf или RGBA8:** offset от rest, где rest = вершины меша = первый кадр. RGBA8 — байт на ось в
  габаритах смещений ассета, если ошибка меньше Max Position Error профиля (§1.2, §1.9, 1.8.3).
- **`_VatRotTex` RGBA8:** кватернион кадра (T, N×T, N) целиком, по 8 бит на компоненту, знак соседних кадров выровнен бейкером (§1.3, §1.9, 1.8.2). Шейдер: `lerp` текселей, декод одним `mad`, однородные N и T без нормализации.
- **Дрейф включён всегда**, настроек у него нет. d кадра — центроид кадра (среднее вертексов в double) минус центроид покоя, хранится float32-массивом строк в `VatAsset`, в шейдер приходит готовым `_VatDrift` (§1.4, 1.8.1); Δ считается от того же float32 d. Телам, которые стоят на месте, он не вредит: у лука ошибка 0.12 мм против 0.21 мм без дрейфа, у воды — те же 0.5 мм. Инспектор ассета показывает ошибку и путь центроида.
- **Память:** 12 Б на вертекс-кадр в текстурах (8 Б с 8-битными позициями), плюс 12 Б на кадр дрейфа в `VatAsset`. Выборок на вертекс — 4 на клип (2 позиции, 2 поворота): 4 у шейдера без бленда, 8 у бленд-шейдера (1.8.2).

**Тангенты и нормали:**
- тангент каждого кадра — скиннутый тангент источника (`BakeMesh`), из UV он не пересчитывается: так normal map совпадает с SMR. Перед построением кватерниона T ортогонализуется к N (Грам–Шмидт), `B = N × T`. у источника без тангентов (Alembic без UV) тангент кадра считается вырожденным и строится правилом ниже;
- знак бинормали — статичный из `tangent.w` покоя; вертексы, у которых знак в кадрах другой, бейкер сообщает предупреждением;
- вырожденный тангент (нулевой или почти параллельный N, `|T − N·dot(N, T)|² ≤ 1e-6` — так выглядят вырожденные UV после импорта) переносится с прошлого кадра того же клипа: `T_k = normalize(T_{k−1} − N_k·dot(N_k, T_{k−1}))`; в кадре 0 каждого клипа — детерминированный базис от N (`x`, если `|N.x| < 0.9`, иначе `y`, после Грам–Шмидта). Клипы друг на друга не влияют;
- после `BakeMesh` нормали нормализуются; нулевая нормаль заменяется на `(0, 0, 1)`, как отсутствующая;
- в меше лежат нормаль и тангент кадра 0 после этих правил; шейдер берёт N и T из `_VatRotTex`, из меша — только `tangent.w`.

**Источники:**
- **SMR → Vertex:** `BakeMesh`, включая блендшейпы. Cloth `BakeMesh` не видит: ткань пишется Alembic Recorder'ом в Play mode, дальше Alembic → Vertex.
- **Alembic, только постоянная топология.** Проверки по всем кадрам бейка: число вертексов, хэш индексов, хэш UV, разбиение на сабмеши. Плюс предупреждение, если вертекс сдвинулся за кадр больше чем на половину баунда меша (половина наибольшей стороны баунда прошлого кадра; сдвиг центроида вычитается, чтобы быстро летящее тело из 1.5 не давало ложных срабатываний). Контракт экспорта: стабильный порядок точек, без перестроения сетки. Проверки не прошли — ошибка «меняющаяся топология — патч 2».
- **Alembic в профиле (1.4):** поле Source — Skinned Mesh Renderer или Alembic; запекается весь Time Range импортёра .abc одним клипом. Все меш-ноды .abc в порядке иерархии — один меш (вертексы подряд, сабмеши подряд), позиции с анимацией xform-нод в пространстве корня .abc. Без нормалей — нулевая нормаль, она заменяется на `(0, 0, 1)`; без тангентов — нулевой, вырожденный тангент. Меш без UV — предупреждение бейка с подсказкой триплэнарного шаблона.
- **Жидкости с постоянной топологией** идут сюда же. Без UV материал триплэнарный.
- **Автоопределение петли** — только подсказка в инспекторе, решает пользователь. В 1.4 (Alembic): max расстояние вертексов между началом и концом Time Range; ≤ 1 мм — петля. Подсказка предупреждает, если флаг Loop с этим не согласен; поиска периода нет — обрезка петли делается Time Range импортёра.

### 2.3 Rigid — разрушения из Alembic (этап Г, подверсии 1.15–1.16)

**Данные** (каналы — §1.9; решения 1.15):
- **Кусок = кость, свой SubGraph `vat_rigid`** (решение пользователя): та же текстура и та же формула, что у Bone (`VatBoneSkin`), но в вертексе одна кость без веса и 16-битный индекс — до 2048 кусков (`W = 2N ≤ 4096`). Бленда нет: у разрушения один клип, `vat_rigid_blend` не делается. Пример — `vat_lit_rigid`.
- **Режим** — поле Mode профиля у источника Alembic: Vertex или Rigid (Bone — только Skinned, Rigid — только Alembic, иначе проблема профиля). Ассет — `VatMode.Rigid`, текстура `_VatPieceTex` (сабассет `_piece`).
- **Куски** — меш-ноды скрытой копии .abc (`MeshFilter` с мешем), матрица — `localToWorldMatrix` в пространстве корня плеера. Меш куска читается один раз; смена топологии — ошибка бейка с рецептом экспорта, меш, который меняется между кадрами (больше 0.01 мм), режется на острова (1.16, см. «Куски»).
- **Меш:** вершины всех видимых кусков подряд, в позе покоя куска; покой — первый запечённый кадр, где кусок виден. Сабмеши кусков сливаются по индексу слота (сабмеш i каждого куска → общий сабмеш i), иначе меш получал бы сабмеш на кусок и рисовался бы только первый.
- **`_VatPieceTex`:** в строках кадров — `(Δ, s)` и `q`, где Δ — смещение пивота от покоя; последняя строка — пивоты кусков `p̃` (см. ниже, округлённые до half).
- **Память:** 16 Б на кусок-кадр; 500 кусков × 150 кадров — 1000 × 151 × 8 Б = 1.2 МБ.
- **Точность:** half смещений от покоя — около 1/2000 пройденного пути (обломок на 10 м — до 4–5 мм). Допуск Rigid — 5 мм, как у предупреждения о fps; выше — предупреждение в логе (у Bone — 1 мм).

**Пивот** — точка минимального ускорения методом наименьших квадратов (одно решение 3×3):
`c* = −(Σ AᵀA)⁻¹ Σ Aᵀb`, где `A = R_{f+1} − 2R_f + R_{f−1}`, `b = t_{f+1} − 2t_f + t_{f−1}`. При плохой обусловленности — центр баунда.
1.15: R и t — движение от покоя `P_f = M_f · M_rest⁻¹`, сумма — по тройкам кадров, где кусок виден во всех трёх, в double.
Плохая обусловленность — `tr(S) ≤ 1e-12` (нет вращения) или `det S ≤ 1e-6·(tr S / 3)³`; вращение вокруг одной
неподвижной оси вырождено (точка оси не определена) и тоже даёт центр баунда. Масштаб куска проверяется как у кости
(`VatBoneCheck`: невязка ≤ 1e-3 и ошибка ≤ 0.5 мм), неравномерный — ошибка бейка, отката в Vertex нет.

**Куски:**
- **Из xform-нод.** Рецепт экспорта: Houdini Packed Transform = Transform Geometry, `s@path` + Build Hierarchy From Attribute. Пошагово — в README репозитория («Экспорт разрушения из Houdini»); способ передать видимость из Houdini не проверен.
- **Fallback, если xform-нод нет** (экспорт Deform Geometry, возможно дефолтный в Houdini **[проверить]**):
  - острова по связности индексов, без сварки по позиции;
  - на каждый кадр подгонка Kabsch/Horn к кадру 0;
  - острова с совпадающими (R, t) на всех кадрах сливаются в один кусок (швы UV и жёстких нормалей режут кусок на острова);
  - критерий куска — максимальная невязка по вершинам и кадрам ≤ 0.5 мм;
  - если хоть один остров не прошёл, бейк падает с отчётом: какие острова и какая невязка.
  - 1.16: решение — по каждой меш-ноде: если её вертексы сдвигаются в осях ноды больше 0.01 мм, нода режется на
    острова (`VatRigidNode`), иначе остаётся одним куском, как в 1.15 — в одном .abc можно смешивать оба вида. До
    первого сдвига подгонка — единичная. Покой — меш на времени 0 (кадр 0); матрица куска — `L2W_ноды · K`, дальше
    обычный Rigid-путь (пивот, видимость ноды, fps-проверка). Подгонка — Horn (кватернион, собственный вектор 4×4
    Якоби, в double): работает и для плоских островов (грань с жёсткими рёбрами). Подгоняются запечённые кадры и
    отсчёты исходника между ними (для fps-проверки). Невязка — в пространстве корня плеера. Слияние: острова по
    убыванию числа вертексов, каждый пробуется к представителю уже собранных кусков; критерий —
    `невязка_B + max по вертексам B и отсчётам |L2W·(K_A − K_B)·v| ≤ 0.5 мм` (сначала дешёвая отсечка по центроиду
    острова). Отчёт — до 10 худших островов, сортировка по невязке.

**Видимость:**
- `s = 0` переключается ступенькой, без lerp;
- `q` и `Δ` берутся от последнего видимого кадра, кадры до первого появления — из первого видимого; кусок, который не появляется ни разу, выбрасывается;
- `q = 0` не писать никогда;
- `N' = normalize(Σ wsRn + 1e-6·n)`.
- 1.15: видимость — `activeInHierarchy` меш-ноды после `UpdateImmediately` (импортёр с Import Visibility выключает
  GameObject xform-ноды); решается только на запечённых кадрах. Ступенька — в данных: шейдер интерполирует `(Δ, s)`
  между кадрами, поэтому кусок появляется и исчезает масштабом от пивота за один интервал кадров. Кусок, скрытый на
  всех запечённых кадрах, выбрасывается из меша и текстуры с предупреждением (первое имя и число). Нормаль у
  `VatBoneDirection` от `s` не зависит (`rot(q, n)/|q|²`), при `s = 0` NaN нет — `+1e-6·n` не нужен.
- `AlembicRecorder` не пишет ноду, скрытую с первого кадра записи до конца: «никогда не видимый» кусок проверяется
  на синтетике.

**Alembic 2.4.5:**
- кадр k семплится вызовом `UpdateImmediately(k / fps)`: аргумент отсчитывается от `StartTime` и зажимается в [0, Duration]. Абсолютное время файла передавать нельзя;
- `frameCount = round(Duration·fps) + 1`; `Duration ≤ 0` или нет мешей — ошибка бейка;
- перед сэмплингом корень плеера ставится в identity;
- вырезать `.abc` из мобильного билда пакет Alembic умеет сам.

**Предупреждение о FPS бейка** — оценка ошибки реконструкции между кадрами бейка: для SMR три внутренние точки на интервал, для Alembic — все отсчёты исходника между кадрами бейка. Порог: 2 мм для персонажей, 5 мм для обломков.
1.15 (сделано только для Rigid): отсчёты исходника — объединение всех time sampling'ов .abc, у пакета Alembic 2.4
публичного API нет, читаются рефлексией (`AlembicStreamPlayer.abcStream.abcContext.GetTimeSampling(i).GetTime(j)`,
абсолютное время минус `StartTime`). Если рефлексия не сработала — три внутренние точки на интервал. В каждой точке —
`lerp` сохранённых half `(Δ, s)` и `q` против матрицы исходника по вертексам куска, только если кусок виден на обоих
концах интервала и в самой точке. Одно предупреждение: число кусков выше порога, худший кусок, ошибка и время. При
fps бейка, равном частоте исходника, внутренних отсчётов нет — предупреждения нет.
