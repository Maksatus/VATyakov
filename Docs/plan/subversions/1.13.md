# 1.13 Bone в игре: LOD и экипировка

_Этап В — Bone, персонажи для толпы. Справочник — `Docs/plan/`, см. `README.md`._

**Входит:**
- LOD-меши одного рига на общей bone-текстуре; bindposes проверяются на равенство;
- экипировка — меш, скиннённый на кость руки, со своим VAT-материалом (§1.6).

Скорость клипа под скорость движения задаёт геймплей через `VatAnimator.Speed` (§2.1), root motion не запекается.

**Решения пользователя (при реализации):**
- доп. меши — список Extra Renderers в профиле: один бейк, одна bone-текстура, меш на каждый рендерер в одном
  `VatAsset` (не отдельный профиль на чужую текстуру);
- экипировка — Mesh Renderer под костью рига, кость — ближайшая кость-предок, хват — положение под костью; SMR
  экипировки тоже можно;
- у доп. рендерера необязательное поле Material: пусто — меш на шаблоне профиля, задано — бейкер пишет в него
  текстуру, как в шаблон;
- откат в Vertex с Extra Renderers — ошибка бейка (Vertex с несколькими мешами — текстура на меш, другой объём);
- смена экипировки в рантайме — забота пользователя пакета (`SetActive`, замена меша), в пакете кода нет, правило — в README.

**Как проверить:** LOD переключаются без скачка позы; оружие в руке не отстаёт.

**Тесты:** LOD с переставленными костями против `BakeMesh` (2 Bones) меньше 1 мм; Mesh Renderer под костью (через
промежуточный объект, со смещением, поворотом и масштабом) совпадает с трансформом по кадрам и лежит в баундах;
проблемы: чужой bindpose, кость вне рига, Mesh Renderer не под костью, другая иерархия, пустой элемент, Mode = Vertex;
неравномерный масштаб с Extra Renderers — ошибка бейка; перебейк сохраняет fileID доп. мешей, пишет материал
доп. рендерера и удаляет убранный меш.
