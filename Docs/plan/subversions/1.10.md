# 1.10 Инструменты: память и «бейк устарел»

_Этап Б — рантайм, общий для всех режимов. Справочник — `Docs/plan/`, см. `README.md`._

Инспектор показывает, сколько стоит ассет и не устарел ли он. Валидатора сборки нет (решение пользователя на 1.10):
меш, текстуры и баунды пишет только бейкер, поэтому fp32-текстуры и `baseVertex ≠ 0` в ассете возникнуть не могут.
Правила для сцен (VAT-меш не Static, не батчится, на нём только VAT-материалы) — в README пакета (§1.1, §1.6).

**Входит:**
- инспектор `VatAsset`, карточка Memory: фактические width × height × байты на тексел каждой текстуры (по самим
  `Texture2D`, а не по раскладке) и padding — пустые тексели последнего блока (`blocks·W − E` на строку, в обеих
  текстурах);
- доля каждого клипа в памяти — в строке клипа (`blocks·W·F` текселей обеих текстур; сумма по клипам = вся память),
  и в инспекторе ассета, и в карточке Result профиля;
- максимальная ошибка в мм с учётом fp16 — карточка Precision (есть с 1.8.3);
- «бейк устарел» (§1.8): хэш исходника и настроек, посчитанный по профилю сейчас, не совпадает с хэшем в ассете —
  предупреждение в инспекторе ассета и в карточке Result профиля. Профиль с проблемами (нет Source, пустой клип)
  хэша не даёт — предупреждения нет. Ассет устаревшего формата показывает свою ошибку «Rebake it».

**Как проверить:** цифры памяти в инспекторе совпадают с Memory Profiler сборки; смена fps, клипов или Max Position
Error в профиле даёт «Out of date» в обоих инспекторах, перебейк его убирает.

**Тесты:** память по текстурам, padding двух блоков, сумма клипов, совпадение с `Profiler.GetRuntimeMemorySizeLong`
(до 4 КБ на заголовок объекта), единицы `B/KB/MB`; «устарел» после смены fps и списка клипов, свежий после перебейка,
профиль без Source — не устарел.
