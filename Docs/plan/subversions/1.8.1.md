# 1.8.1 Дрейф на CPU

_Этап Б — рантайм, общий для всех режимов. Справочник — `Docs/plan/`, см. `README.md`._

Дрейф d — сдвиг всего тела, одно число на кадр, одинаковое для всех вертексов draw. До 1.8.1 шейдер читал его из
`_VatDriftTex` на каждом вертексе: 4 тексела на клип (2 кадра × hi/lo), 8 во время перехода — половина выборок
вершинной стадии и 2/3 выборок позиции (тени, depth). Цель — слабые телефоны (Redmi 9A, PowerVR GE8320).

**Входит:**
- `VatAsset` хранит d по строкам: `Vector3[]` во float32, длина `totalRows`. `_VatDriftTex`, сабассет `_drift` и кодек
  hi/lo убраны, `formatVersion` 4. Перебейк ассета формата 3 удаляет его сабассет `_drift`.
- Свойство `_VatDrift = (d, 0)` в SubGraph `vat_vertex` (Precision Single, Hybrid Per Instance). Шейдер:
  `pos = rest + _VatDrift.xyz + lerp(Δ_A, Δ_B, w)`; вход `DriftTex` у `VatVertexPosition` удалён, вход `Drift` — последним.
- CPU (`VatAsset.Drift`): `d = lerp(lerp(d[A.row0], d[A.row1], A.frac), lerp(d[B.row0], d[B.row1], B.frac), w)`.
  `VatAnimator` пишет `_VatDrift` вместе с `_VatFrame*`; `ApplyTo`, поле Frame инспектора материала и `VatCompare` — тоже.
- Бейкер считает `Δ = pos − rest − d` от float32 d.
- VatDev перезапечь: лук (default, upgrade, one_shot), воду, желе.

Ветвления по w нет (решение 1.8): клип B читается всегда.

**Как проверить:**
- желе в сцене `drift` на 40 м не дрожит и совпадает с Alembic;
- лук в `compare` совпадает с SMR на Fire кадр 20;
- толпа в `animator` с CrossFade и Manual плавная;
- в шейдере 4 выборки на клип (2 позиции, 2 поворота), `_VatDriftTex` нет;
- ошибка в инспекторе ассета не больше прежней (лук 0.122 мм, желе 0.059 мм, вода 0.503 мм).

**Тесты:** `VatAsset.Drift` — интерполяция по frac и по w, при `_VatFrameB = 0` — дрейф клипа A; реконструкция
`rest + d + Δ` против источника по массиву дрейфа; ассет формата 3 не играет; перебейк не оставляет сабассет `_drift`;
в сгенерированном коде `float4 _VatDrift`, Hybrid Per Instance, без `_VatDriftTex`.
